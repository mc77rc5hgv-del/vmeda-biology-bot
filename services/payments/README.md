# СБП codeePay

API: https://codeepay.ru/docs и https://codeepay.ru/openapi.json. Ключ передаётся только
сервером через `X-Api-Key` на `https://codeepay.ru`. `POST /initiate_payment` создаёт счёт
с `method_slug=sbp` и суммой в рублях. `POST /get_payment` возвращает финансовое подтверждение.
Реальный API также возвращает checkout на `https://payment.codeepay.xyz/transfer/...`.
Ключ никогда не передаётся платёжной странице, клиенту или журналу приложения.

## Хранение и подтверждение

`billing.sqlite3` создаётся отдельно на **том же оригинальном `/data` владельца бота**.
Существующие учебные таблицы и пользователи не мигрируют. Создание неоплаченного счёта
вообще не записывает `stats.json`. Журнал хранит серверную цену в целых копейках, источник
(bot/miniapp), пользователя, username на момент создания, ID провайдера, статусы, комиссию,
зачисление и историю переходов. Пользователь видит только свои платежи. Полный финансовый
журнал доступен только администраторам: бот → админ-панель → «Платежи СБП codeePay»,
либо защищённый `/api/v1/subscriptions/admin/sbp` (по 50 записей, offset).

Webhook API не документирует криптографическую подпись. Поэтому уведомление **не является
доказательством оплаты**: секретный callback лишь запускает новый запрос статуса с API-ключом
продавца. Нельзя зарегистрировать неизвестный заказ через webhook. Платёж применяется только
если `payment_deposited=true`, совпадают СБП-метод, ID заказа провайдера, внутренний ID,
случайный merchant proof, исходная сумма и валюта, а сумма зачисления и комиссии равна оплате.
Provider IP в документации: `82.97.245.146`; при настройке ingress-фильтра доверять следует
проверенному адресу соединения, а не произвольному пользовательскому `X-Forwarded-For`.
Серверная перепроверка обязательна независимо от IP.

OwnerGuard остаётся закрытым: публичный gateway передаёт webhook владельцу по уже существующему
секретному transport, без открытия внутренних API. Ответ webhook — HTTP 200 после обработки;
при недоступности провайдера — 503 для повторной доставки. Фоновая проверка всех незавершённых
зарегистрированных счетов продолжается после закрытия приложения и перезапуска бота.

Выдача подписки, receipt и запись покупки сохраняются одной атомарной записью `stats.json`.
Только после подтверждённой записи на диск журнал помечается applied. При сбое между файлами
receipt позволяет восстановить applied без повторной выдачи. Повторные callback не добавляют
срок дважды. Сохраняются прежние пользовательские поля, AI-счётчики, срок и исходная подписка
в receipt. Если покупка теперь сократит уже оплаченные права/срок, деньги фиксируются со статусом
review, а текущая подписка сохраняется для проверки поддержкой.

API не документирует идемпотентное создание или поиск по merchant metadata. Поэтому счёт
резервируется до HTTP-вызова; дубли возвращают сохранённый checkout. Таймаут создания помечается
creation_unknown и не вызывает слепого повторного создания. Такие заказы нужно сверить в кабинете
провайдера. Автоматические списания, возвраты и выплаты не выполняются.

## Настройка (только на owner-сервисе)

- `CODEEPAY_ENABLED=true` (по умолчанию false).
- `CODEEPAY_API_URL=https://codeepay.ru`.
- `CODEEPAY_API_KEY` — приватный ключ продавца.
- `CODEEPAY_WEBHOOK_SECRET` — случайная строка не короче 32 символов.
- `CODEEPAY_CALLBACK_BASE_URL` — публичный HTTPS URL существующего API gateway.
- `CODEEPAY_TIMEOUT_SECONDS=15`.

СБП добавлена рядом с действующими Telegram Stars и **переводом на карту с ручным подтверждением**.
Цена, тариф и субъект подписки берутся из единого каталога владельца. Redirect/browser callback
не меняет доступ. Miniapp хранит ID незавершённого платежа и показывает общую историю СБП из бота.
