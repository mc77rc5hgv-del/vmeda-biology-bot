# ТЗ (расширение): бот @Vmeda_anatom_bot и связка с веб-приложением «АНАТОМ»

> Статус: спецификация / ТЗ на будущую реализацию. Этот документ фиксирует архитектуру нового бота
> `@Vmeda_anatom_bot`, который **не является** веткой/форком `telegram_bot.py` из этого репозитория и не
> использует его JSON-контент-модель. Это отдельный проект: бот выступает "входной дверью" и "будильником" для
> веб-приложения «АНАТОМ» (`Анатом.dc.html`), а не самостоятельным контентным ботом с флеш-карточками/тикетами,
> как `vmeda-biology-bot`. Хранится здесь как справочный документ до момента, когда будет решено, в каком
> репозитории вести реализацию.

## Роль бота в системе

Бот выполняет три функции:

1. **Вход (аутентификация)** — мост между Telegram-идентичностью пользователя и сессией на сайте.
2. **Напоминания (мотивация)** — единственный канал push-уведомлений вне сайта.
3. **Мост Telegram ↔ веб-приложение** — быстрые сводки прогресса и deep-link на сайт.

Приложение остаётся основным местом обучения; бот — не замена ему, а вход и будильник.

## 1. Аутентификация (ядро связки)

Пошаговый флоу:

1. На экране входа сайта — кнопка **Telegram Login Widget**.
2. Пользователь жмёт → Telegram спрашивает подтверждение → возвращает объект
   `{id, first_name, last_name, username, photo_url, auth_date, hash}`.
3. Сайт шлёт объект на сервер: `POST /auth/telegram`.
4. Сервер проверяет `hash` (HMAC-SHA256 с токеном бота) — доказательство, что данные реально от Telegram, а не
   подделка.
5. Сервер создаёт/находит пользователя в БД по Telegram `id`, выдаёт сессию.
6. Сайт тянет сохранённый прогресс этого пользователя с сервера.

**Что это даёт:** один аккаунт = один Telegram `id`. Прогресс, XP, стрик привязаны к человеку, а не к браузеру —
зашёл с телефона и с компьютера, видит одно и то же.

## 2. Команды бота (внутри Telegram)

| Команда | Поведение |
|---|---|
| `/start` | Приветствие, короткое описание, кнопка-ссылка «Открыть АНАТОМ» (ведёт на сайт). Если пользователь пришёл по deep-link `?start=<код>` — привязывает сессию входа. |
| `/study` | Кнопка «Открыть приложение» + строка «сегодня к повторению: N тем» (данные с сервера). |
| `/progress` | Сводка из БД: уровень, XP, стрик, сколько тем сдано, средняя точность. Быстрый взгляд без открытия сайта. |
| `/review` | Сколько тем «созрело» к интервальному повторению сегодня + кнопка перехода. |
| `/streak` | Текущая серия дней 🔥 и предупреждение, если серия под угрозой (сегодня ещё не занимался). |
| `/reminder` | Включить/выключить и настроить время ежедневного напоминания. |
| `/help` | Список команд, ссылка на поддержку. |

## 3. Напоминания (push-мотивация)

Бот — единственный способ дотянуться до студента вне сайта:

- **Ежедневное напоминание** в выбранное время: «Пора закрепить анатомию 🦴 N тем ждут повторения» + кнопка.
- **Защита стрика** — вечером, если пользователь сегодня не занимался: «🔥 Серия 12 дней под угрозой! 5 минут — и
  она сохранится».
- **Возврат неактивных** — если не заходил >14 дней: «Скучаем! Продолжи с темы …».
- **Достижения** — «Ты сдал раздел Спланхнология на 90% 🎉».

Технически: сервер по расписанию (cron) берёт из БД `chat_id` и настройки, шлёт сообщения через Telegram Bot API.
Именно поэтому вход через Telegram ценен — бот получает право писать пользователю.

## 4. Синхронизация данных (двусторонняя связь)

| Направление | Что происходит |
|---|---|
| Сайт → сервер | При каждом действии (тест, карточка, повтор) прогресс сохраняется на сервер (`PUT /api/state`, дебаунс). |
| Сервер → сайт | При входе сайт загружает состояние (`GET /api/state`) — сервер источник правды. |
| Сервер → бот | Cron и команды читают из БД, чтобы слать точные цифры в Telegram. |
| Бот → сервер | `/reminder` меняет настройки уведомлений в БД. |

**Структура состояния** (уже задана фронтендом, не менять): `progress, mistakes, favorites, notes, xp, streak,
lastActive, history, dayDone, dayKey, dayGoal, lastTopic, examDone, termLang, reminders`.

## 5. БД (Postgres на Railway)

```
users:
  id            PK, Telegram id
  username
  first_name
  last_name
  photo_url
  chat_id
  created_at

user_state:
  user_id       FK -> users.id
  state         JSONB   -- см. "Структура состояния" выше
  updated_at

reminders:
  user_id       FK -> users.id
  enabled
  time
  tz
  last_sent
```

## Итоговая картина

```
[Студент] ──вход──> Telegram Login Widget ──> Сервер (Railway)
                                                  │ проверка hash
                                                  ▼
                                          Postgres (users, state)
   ▲                                              │
   │ напоминания (cron)                           │ прогресс
   │                                              ▼
[Бот @Vmeda_anatom_bot] <──── читает БД ──── Веб-приложение (Анатом.dc.html)
```

- **Приложение** — учёба, тесты, тренировки, атлас.
- **Бот** — вход + напоминания + быстрые сводки.
- **Сервер + БД** — общая память между ними.
